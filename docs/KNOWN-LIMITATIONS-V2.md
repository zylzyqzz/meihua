# 已知限制与故障恢复 V2

## 已知限制

- 媒体数字人首版按音频主时钟切换和纠偏预录动作片段，不提供逐音素口型；逐音素口型必须接入能消费口型参数的 Live2D/3D 模型。
- 透明 WebM 优先；MP4 使用 OBS 色度键；PNG/WebP 只作静态回退。
- 视频分辨率、时长和透明通道目前标记为待外部媒体工具核验，上传校验不虚构这些元数据。
- 字幕按真实 WAV 总时长进行分句分配，不声明逐词时间戳。
- VTube Studio、Warudo、外部 LLM 和外部 TTS 为 `RESERVED`。
- TikFinity 字段契约已实现，但在保存真实脱敏样本前只能称“适配完成，待真实联调”。

## 故障恢复

### TikFinity 断线

系统暂停新事件接入并自动重连；当前场次、队列、榜单和 OBS 状态保留。连接恢复后先在“接入验证”确认真实事件计数再恢复接入。

### TTS 失败

任务不会进入伪口播。重试失败后进入 ERROR，审计日志保存错误。修复语音后使用“重答当前”创建新任务，不覆盖原失败任务。

### 人物素材失败

动作槽位按 `fallbackAction` 回退；最终回到 IDLE 静态素材。若引用文件缺失，开播预检失败。

### OBS 来源关闭或重开

重新打开来源后先读取完整 V2 快照，再按服务端时间恢复当前 Cue 和字幕位置，不从头重新推测流程。

### 程序崩溃/重启

未结束场次恢复为 `PAUSED`，遗留活动 Cue 被安全结束。管理员确认数据库、TTS、TikFinity 和 OBS 后手动恢复接入。

### 数据库故障

停止自动处理，保留错误证据。首次 V2 迁移前备份位于 `data/meihua-live.db.pre-v2.bak`。恢复前同时备份当前 `.db`、`.db-wal` 和 `.db-shm`，不要直接覆盖正在运行的数据库。

### 紧急收播

使用“立即收播”中止当前任务并记录原因；正常情况下优先使用“正常收播”，等待当前任务完成后归档场次。

## V2.2 增补

- `meihua-stage` 的浏览器视觉验收在本机当前会话无法执行（ZCode 内置浏览器 webview 未挂载），已用服务端渲染冒烟测试与 10 场景接口契约校验代替；真实浏览器截图与 OBS 录制仍为外部阻断。
- 免费排队过期逻辑在 pipeline 入口执行，自动化无法快进时钟；需要实播观察或引入可注入时钟后再验证。
- 数字人供应商适配层默认使用本地模拟；任何第三方人物/口型/云端视频能力在完成真实账户、授权、绿幕输出与 OBS 录制前不标记为已接入。
