# 梅花直播中控个人使用攻略

更新日期：2026-08-30

适用对象：梅花老师本人。日常只需要操作后台，不需要碰模型目录、接口地址或代码。

## 一、你只需要记住三件事

1. 第一次先运行 `1-环境检查与安装.bat`，之后双击 `2-启动系统.bat`。
   首次安装会自动执行并关闭；日常启动不会再显示多个服务黑窗口，排错日志统一位于整包根目录 `logs/`。
2. 后台：`http://127.0.0.1:5200/`
3. OBS 唯一地址：`http://127.0.0.1:5173/obs/source/meihua-stage`

顶部直播控制只做两件事：

- **立即开播**：开始接收并处理直播任务。
- **关闭直播**：停止接收新任务并结束本场。

画面、人物或声音修改后，必须点击对应的“保存并发布”或“保存并使用”；只在页面里改但没有保存，不会影响正在播出的内容。

## 二、第一次使用

### 1. 克隆一个声音

进入“数字人中心”，打开第 1 步“声音克隆”。

1. 选择这个声音要使用的语言，例如中文或 English。
2. 上传 10–30 秒清晰人声。支持 WAV、MP3、FLAC、M4A、MP4、MOV、WebM。
3. 点击“开始克隆”。
4. 系统自动提取声音、识别样音原文并调用 GPT-SoVITS 生成试听。
5. 右侧声音库出现“可用”后，点击播放试听。

不需要手工填写参考原文，也不需要选择模型文件。只有能真实播放试听的声音才会进入可用列表。

样音建议：

- 只有一个人说话。
- 没有背景音乐、回声和明显噪音。
- 正常语速，情绪稳定。
- 使用者已经确认声音授权。

### 2. 克隆一个数字人

打开第 2 步“数字人克隆”。

1. 上传一段正面单人物 MP4、MOV 或 WebM 视频。
2. 点击“开始克隆”。
3. 系统自动转码、检测人脸并建立 MuseTalk 人物缓存。
4. 人物库显示“可用”后，点击“预览人物”检查画面。

克隆时不会额外生成一段试口型。实际测算开始时，系统才会根据真实播报声音逐句生成口型。

人物视频建议：

- 竖屏、单人、正脸清楚、嘴部无遮挡。
- 镜头稳定，光线均匀，头部不要大幅转动。
- 建议 10–30 秒；系统会统一处理成 30fps 浏览器兼容视频。
- 正式直播使用无水印且已确认授权的素材。

### 3. 选择使用

打开第 3 步“选择使用”。

1. 选择一个状态为“可用”的数字人。
2. 选择一个状态为“可用”的声音。
3. 点击“保存并使用”。

从下一条测算开始，系统自动使用这组人物和声音。正在播报的任务不会中途换人或换声。

## 三、配置直播画面

进入“画面工作台”。

1. 左侧点击图层名称，右侧调整位置、尺寸、透明度、文字和素材。
2. 只有拖拽把手负责上下排序；点击图层其他位置只负责选中。
3. 眼睛控制显示，锁控制是否允许拖动。
4. “一键透明/仅显示内容”会去掉底板、边框和阴影，只保留内容。
5. 直播画面中的固定文字必须使用英文或你自己填写的目标语言。
6. 礼物窗口只显示图标和自定义文案，不显示礼物名称、ID 或价格。
7. 背景视频必须等素材状态变成“可使用”再选择。
8. 调整完成后点击“保存并发布到 OBS”。

工作台是草稿，OBS 是上次发布版本。这样编辑时不会拖慢 OBS，也不会把半成品推到直播画面。

## 四、配置 OBS

OBS 只添加一个浏览器来源：

- 地址：`http://127.0.0.1:5173/obs/source/meihua-stage`
- 宽：1080
- 高：1920
- 帧率：30fps
- 浏览器来源保持静音
- 不添加第二个梅花舞台，也不添加 `/obs/source/audio`

声音设置：

1. Windows 输出选择 `CABLE Input (VB-Audio Virtual Cable)`。
2. OBS 采集 `CABLE Output`。
3. 确保 OBS 中只有这一条梅花声音来源。

这套结构可以避免人物视频自带声音、浏览器声音和 Windows 声音同时播放。

## 五、资格、礼物和队列

进入“资格与队列”配置点赞、评论和礼物规则。

- 评论资格关键词使用中文顿号 `、` 分隔，不限制数量。
- 礼物规则使用真实 TikTok 礼物 ID，后台填写币值、测算时长和自定义文案。
- 直播画面只显示礼物图标和自定义文案；价格、票数、ID 只给管理员看。
- 获得资格但还没提问的观众进入“待提问”。
- 已经提问的观众进入正式队列，并优先于尚未提问的资格。
- 礼物和点赞来源保留区分；同一优先级内按提问完成时间排序。
- 正在测算的用户不会被后来的礼物任务强行打断。

保存规则后，先用本地排练或真实小号事件验证一次。

## 六、每次开播的八步

1. 启动 TikFinity 并登录本次直播账号。
2. 双击 `2-启动系统.bat`。
3. 打开后台和 OBS。
4. 检查资格、礼物和队列规则。
5. 在画面工作台确认画面并“保存并发布到 OBS”。
6. 在数字人中心确认当前人物和声音都显示“可用”。
7. 用一条短文案或本地排练完成声音和口型测试。
8. 确认画面、声音、队列都正常后，点击“立即开播”。

收播时点击“关闭直播”，等待当前播报结束，再保存 OBS 录像。

## 七、系统在播报时会自动做什么

你不需要手工编排口型或动作。每条测算由后端自动完成：

1. 根据当前声音语言生成解读。
2. 把解读拆成适合播报的句子。
3. 用当前克隆声音生成 WAV。
4. 用当前数字人和同一 WAV 生成静音口型视频。
5. 舞台准备好人物视频后，再从唯一音频总线播放声音。
6. 播放当前句时准备下一句；来不及时进入等待动作，不允许声音先播、嘴型未到。

## 八、常见问题

### 声音一直不是“可用”

- 先点击重新处理并查看具体错误。
- 样音必须有清晰人声，不能是静音或只有音乐。
- MP4 必须包含音轨。
- GPT-SoVITS 9881 未启动时，系统不会假装克隆成功。

### 数字人一直不是“可用”

- 视频必须有人脸且嘴部清楚。
- MuseTalk 9898 未启动时，人物只能保留为待处理，不能假装完成。
- 重新上传前先确认源视频能正常播放。
- CPU 处理可能较慢；RTX 3060 12GB 会明显更快。

### 有声音但人物不动

- 确认当前人物和声音都为“可用”并已“保存并使用”。
- 检查 MuseTalk 是否在线。
- 检查 OBS 舞台是否仍加载唯一正式地址。
- 修复后重试原任务，不要重复建立同一测算。

### 出现双声

- OBS 浏览器来源必须静音。
- 数字人口型 MP4 不应带音轨；系统会拒绝旧链路的重复声音设计。
- OBS 只保留一个 `CABLE Output` 采集来源。

### OBS 和工作台不一样

- 点击“保存并发布到 OBS”。
- 查看工作台和 OBS 是否显示同一场景版本。
- OBS 地址必须是 `/obs/source/meihua-stage`。
- 只刷新一次 OBS 浏览器来源，不要连续刷新。

### 背景视频黑屏或重复一秒

- 重新上传视频，等自动转码完成后再发布。
- OBS 不要设置成场景切换时反复刷新浏览器。
- 不要同时添加多个相同背景视频图层。

### TikFinity 报服务器不可用

- 这是 TikFinity 自身网页组件或网络连接问题，不代表梅花声音和数字人模型损坏。
- 修复 TikFinity 后必须收到一次真实事件，才能确认直播接入恢复。
- 接入未恢复时可以本地排练，但不要正式接单。

## 九、日常备份

定期备份一体包中的：

- `app\data\meihua-live.db`
- `app\data\media\`
- `app\data\voices\`
- `app\data\backups\`

人物模型、声音模型和程序依赖已经包含在整包目录中。不要只复制数据库而漏掉素材和声音文件。

## 十、当前真实边界

- 声音克隆和视频口型已经过真实链路验证，不是模拟按钮。
- CPU 可以跑完整流程，但速度不是正式直播基线。
- RTX 3060 12GB 上仍要做 30 条连续测算和 2 小时 OBS 录制，才算完成最终性能验收。
- TikFinity、OBS、VB-CABLE 和云端备用服务仍需要现场账号、驱动和设备配合。

真实技术状态以 [数字人中心当前真实状态](DIGITAL-HUMAN-CENTER-STATUS.md) 为准。
