## 对梅花最有价值的借鉴点

1. **一键包不是“一个脚本拉起所有窗口”**：应由一个桌面守护/启动器管理服务清单，后台静默启动，窗口只给用户展示“启动中、可用、需要处理”三种状态。
2. **服务与界面分离**：梅花的 TikFinity 接入、语音合成、数字人渲染、OBS 舞台都应拥有独立的真实 health、日志和重启策略；中控只订阅状态，不直接承担子进程生命周期。
3. **运行数据与程序分离**：数据库、素材、缓存、日志和临时渲染文件应放入明确的数据目录；升级程序时不覆盖用户的场景、声音和人物档案。
4. **组件清单驱动的环境检测**：OBS、VB-CABLE、TikFinity、GPU 驱动、GPT-SoVITS、MuseTalk、FFmpeg 均应通过同一清单检测“已存在 / 可复用 / 需安装 / 失败原因”，避免当前包里出现“已经安装 OBS 却提示重装”的问题。
5. **单一事件网关**：无论来自 TikFinity、演练数据还是未来经审核的平台适配器，最终都先转为梅花自己的 `LiveEvent`，再进入去重、资格、队列、起卦和播报流程。

后续如果开始“继续改造多配置任务”，可把上述五点作为独立的“运行时与安装体验”工作流纳入实现；仍只会自主开发等价能力，不会接入或依赖这款软件的二进制模块。
