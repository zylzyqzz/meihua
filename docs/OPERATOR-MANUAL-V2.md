# 中控操作手册 V2

## 开播前

1. TikFinity 已由梅花中控自动拉起（桌面端/启动脚本都会带起；已运行则跳过）。仅首次需要人工设置：TikFinity 左侧 Connect TikTok Account 登录开播账号一次；Setup 页 Your TikTok Name 填主播名。Points/等级等功能与中控无关，保持默认。之后中控启动会自动带起它，无需再管。
2. 运行 `pnpm start:live`，打开 `http://127.0.0.1:5200/`。
3. 在“OBS 画面”上传并选择待机人物、说话人物、礼物感谢人物和背景。
4. 在同一页面逐项选择 IDLE、CASTING、SPEAKING、GIFT、QUEUE、ERROR 查看预览。
5. 在“简单设置”确认点赞次数、免费排队时间、评论词、礼物时长、文字、字体和颜色后保存。
6. 在 OBS 逐一添加正式 `/obs/source/*` 地址，`audio` 只添加一次。
7. 回到“直播导演台”，检查数据库、场景、TTS、TikFinity和素材预检。
8. 真实直播必须等 TikFinity 实际收到事件；“允许警告开始排练”只用于本地排练。

## 开播

- “通过预检后开始直播”：所有 FAIL 必须清零，创建新场次并锁定场景版本。
- “允许警告开始排练”：允许 TikFinity/数字人素材警告，只用于本地排练。
- 开播后草稿仍可编辑，但不会影响当前场次；只有下一场发布版本会使用新样式。

## 日常导演操作

- “暂停接入”：停止接收新直播事件，保留当前任务、队列、榜单和 OBS 状态。
- “恢复接入”：继续接收 TikFinity 事件。
- “跳过当前”：中止当前任务并进入下一位，写入审计。
- “重答当前”：创建明确的人工重试，不覆盖原任务证据。
- “强制待机”：结束当前显示 Cue，恢复待机；仅用于应急。
- “正常收播”：停止收题，等待当前任务结束，然后冻结并归档本场数据。
- “立即收播”：立即中止当前任务，必须填写或保留中止原因。

## 简单设置与队列

- 点赞只设置“多少次获得一次机会”；评论只填写触发词；免费队列只设置一个过期分钟数。
- 礼物 ID 优先匹配，名称回退；连击礼物只在最终帧结算。
- 用户先送礼后评论时，权益在有效期内自动套用。
- 已在队列中送礼时，优先级、时长和顺序立即更新。
- 当前正在测算时送礼不会打断当前任务，只触发感谢并保存下一次权益。
- 免费资格过期后自动移出队列，需要重新点赞或评论取得资格；礼物用户进入队列后不自动过期。

## 画面设置

- “简单设置”只暴露显示文字、输出语言、字体、字号和三种颜色。
- 宽高、动作时长、语速、字幕切句、卦象焦点和同步计时由系统固定管理，不要求操作者配置。
- “OBS 画面”点击模块即可预览、打开独立小窗口或复制正式地址，位置和层级直接在 OBS 拖动。

## 收播后

1. 正常收播并确认场次状态 ENDED。
2. 在“记录与榜单”检查本场任务、礼物榜和互动榜。
3. 在“审计日志”检查人工操作、音频事件和异常。
4. 导出或备份 `data/meihua-live.db`、录像和真实字段脱敏样本。

## 严禁

- 不得把本地 Mock 当作 TikFinity 实播验证。
- 不得在 OBS 添加两个 `audio` 来源。
- 不得在直播中发布场景并期待当前场立即变化。
- 不得删除仍被场景版本引用的素材。
- 不得以“地址已保存”代替“服务已连接”。
